# Portfolio v2 — Saikrishna Vennam

A multi-tab, animated personal portfolio. **Theme: "live data terminal / streaming pipeline"** — deep navy-black, electric lime + cyan, monospace + display type. Deliberately different from the old Portfolio repo (which was a plain Data Engineer page). Navigation is a sticky tab bar — Home, About, Experience, Projects, Skills, Education, Contact — one tab visible at a time, with hash routing (`#home`, `#projects`, …) so each tab is deep-linkable and back/forward buttons work.

## Files

| File | What it is |
|---|---|
| `index.html` | The whole page: hero, About, Experience timeline, featured Projects, live repo grid, Skills, Education, Contact |
| `styles.css` | All styling, animations, responsive layout (mobile-first breakpoints at 860px) |
| `script.js` | Typewriter roles, hero particle canvas, animated counters, scroll-reveal, skill bars, hash-routed tab switching, live GitHub fetch + fallback |
| `.github/workflows/update-stats.yml` | Weekly GitHub Action that writes `projects.json` (see Automation) |
| `projects.json` | Generated by the workflow — do not edit by hand. Absent until the first run; the site works without it. |
| `resume.pdf` | The real base resume PDF (added by the parent). The "Download Resume" buttons link to it. |

- **Counters:** 7,049,869 flights · 69,985 patients · 1,300+ clinics · 40% manual reporting cut — count up when scrolled into view. All numbers are verified real figures.
- **Ticker:** a scrolling "pipeline status" strip under the nav.
- **Scroll-reveal** sections, **animated skill bars**, hover-lift cards. Respects `prefers-reduced-motion`.

## Automation — how projects stay current without editing HTML

1. **Live, in the browser (`script.js`):** on first visit to the Projects tab (or on load if the URL is `#projects`), the page fetches `https://api.github.com/users/Saikrishna-469/repos?sort=updated&per_page=100` and renders the 9 most recently updated non-fork repos as cards (name, description, language, stars, updated date). New repos appear automatically. The fetch runs once per page load.
2. **Fallback:** if the API fails or is rate-limited (unauthenticated GitHub API calls are rate-limited per IP), the page renders a curated fallback list of the 4 real repos instead — it never shows an empty section. The badge changes to "showing curated list — GitHub API unavailable".
3. **Weekly snapshot (`.github/workflows/update-stats.yml`):** runs Mondays 09:00 UTC and on every push to `main`. Using the built-in `GITHUB_TOKEN` (no secrets to configure), it fetches the same repo list, writes `projects.json` with `generated_at`, `repo_count` and per-repo details, and commits it back if changed. `script.js` reads `projects.json` when present and adds the snapshot date/repo count to the footer. If the workflow ever fails, the live API + fallback still cover the Projects section.

## Deploy (parent / user step — replaces the old repo)

```bash
cd portfolio-v2
# add the real resume first:
cp /path/to/saikrishna-vennam-resume.pdf resume.pdf
git clone https://github.com/Saikrishna-469/Portfolio.git Portfolio   # or reuse an existing clone
cd Portfolio
git rm -r . ; cp -r ../portfolio-v2/. .   # replaces index.html / script.js / styles.css
git add -A && git commit -m "Portfolio v2: animated streaming-pipeline theme, live GitHub projects" && git push
```

Then enable GitHub Pages: repo **Settings → Pages → Deploy from a branch → main / (root)**. The site is live at `https://saikrishna-469.github.io/Portfolio/`. No build step — it is plain HTML/CSS/JS.

## Local check

Open `index.html` in a browser (or `python3 -m http.server` in this folder, then visit `http://localhost:8000`). The live GitHub fetch needs internet; if the API is rate-limited locally, the curated fallback renders instead — that is expected behaviour, not a bug.
